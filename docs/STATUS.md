## 驗證結果

### 修 `pnpm joy open` 被當成 cross-site 擋下（2026-11-25，分支 `fix-joy-open-navigation`）

- **問題**：擁有者在 Brave 執行 `pnpm joy open`，頁面只顯示 `{"error":"Origin is not allowed"}`，網址列留著 `#token=…`（擁有者截圖，權杖因此外流，已請擁有者換一組）。原因：從 `file://` 的暫時網頁跳到 `http://127.0.0.1` 時，瀏覽器送 `Sec-Fetch-Site: cross-site`，而 server 對任何 cross-site 請求都回 403，連網頁本身都載不到，網頁也就沒機會把權杖從網址拿掉。#181 的 e2e 直接開 `/#token=…`，沒走暫時網頁，所以沒抓到。
- **做法**：`packages/server/src/server.ts` 的 cross-site 規則只放行「整頁載入」：GET／HEAD、不是 `/api`、`Sec-Fetch-Mode: navigate` 且 `Sec-Fetch-Dest: document`。建好的網頁不含任何秘密，載入也不改任何東西；API、iframe、script 的 fetch、POST 仍然擋。
- **測試**：server 新測試（先失敗、修後通過）：跨站整頁載入 `/` 不是 403；跨站的 `/api/repos`、iframe、`cors` fetch、POST 仍是 403。真實 Chromium（Playwright）：另起一個用分支程式碼、暫時 `JOY_HOME` 的 Joy（4391），用 `openJoy` 寫暫時網頁並在瀏覽器打開：文件 200、沒有 Origin 錯誤、沒有權杖頁、網址沒有 `#token`、權杖已存、沒留下 `open-*.html`。curl 重現：帶 `sec-fetch-site: cross-site` 的舊版回 403。根目錄 `pnpm check` 通過。
- **沒驗證到**：擁有者的 Brave 實際再跑一次（要先換權杖、重新啟動服務）。

### Codex 不跑擁有者的 hooks（2026-11-25，分支 `codex-no-owner-hooks`）

- **問題**：Joy 的 Codex app-server run 會執行擁有者 `~/.codex/hooks.json` 裡的 hooks（目前是 reason-network 的 session／prompt／tool／stop hook 與一個研究腳本）。hook 會執行指令，不經過 Joy 的核准，也讓 Joy 的 run 被回報到別的系統。exec 的 `--ignore-user-config` 只略過 config.toml，`hooks.json` 是另一個檔案。
- **做法**：app-server 啟動參數（`OWNER_EXTRAS_OFF`）與 exec 參數都加 `--disable hooks`（codex-cli 0.166.0 有這個 feature）。Joy 本身不用 Codex hooks。
- **測試**：providers `app-server.test.ts`、`args.test.ts`（兩種 transport 的參數都有 `--disable hooks`）。真實 CLI（gpt-6-luna、low）：app-server 一個 turn 的 `hook/*` 事件 8 → 0、run 照常完成；exec 加上後照常完成；repo 自帶的 `.codex/hooks.json` 在兩種 transport、開或關都沒有執行（未信任的專案）。根目錄 `pnpm check` 通過。
- **沒驗證到**：exec 原本是否會跑擁有者的 hooks（從外面看不到 hook 事件，也沒有為了測試去改擁有者的 `hooks.json`）；不論如何現在都關掉了。

### Codex app-server 回報 token 用量（2026-11-25，分支 `codex-app-server-usage`）

- **問題**：只有 exec 解析 `usage`；預設的 app-server transport 從來沒把 token 用量交給 Joy，所以 Codex 的 run 不會出現在任務用量、統計「用量分布」，也量不到 `promptOnly` 省了多少。
- **做法**：`CodexAppServerParser` 接 `thread/tokenUsage/updated`（真實 CLI 確認在 `turn/completed` 之前送達）：第一次收到時記下「這個 turn 之前」的累計（`total − last`），之後只更新最新的 `total`，turn 結束時送出一個 `usage`（input 含快取、cached、output 的增量）。重複的回報不會重算，續用的 thread 不會算到之前的 turn，失敗的 turn 也會算。
- **測試**：`app-server.test.ts`（續用 thread、多次請求、重複回報只算一次；失敗的 turn 有用量；沒有回報就不送）。真實 app-server（gpt-6-luna、low）：一般 run 送出 `usage` input 25,833；`promptOnly` 14,124。根目錄 `pnpm check` 通過。
- **另外發現**：app-server 的 run 會跑擁有者 Codex 的 hooks；已在 `codex-no-owner-hooks` 關掉（見上一節）。

### Codex 只帶 prompt（2026-11-25，分支 `codex-prompt-only`）

- **問題**：`RunOptions.promptOnly` 只對 Claude 有效，Codex 照樣載入專案 AGENTS.md、web search 與全部內建工具。
- **做法**：`packages/providers/src/codex-cli/args.ts` 的 `PROMPT_ONLY_FEATURES`（`shell_tool`、`unified_exec`、`view_image`、`image_generation`、`memories`、`goals`）與 `PROMPT_ONLY_CONFIG`（`project_doc_max_bytes=0`、`web_search="disabled"`）。exec 加 `--disable …` 與 `-c …`；app-server 在 `thread/start` 的 `config` 用點號 key 合併（整個 `features` 表會蓋掉擁有者的設定，實測讓擁有者的 MCP server 又跑起來，被 Joy 的檢查擋下）。只放實測有省的 feature，因為不存在的名字會讓 Codex 拒絕啟動。擁有者的 `CODEX_HOME/AGENTS.md` 仍會載入。細節在 `docs/spikes/codex.md`。
- **測試**：providers `args.test.ts`（promptOnly 的參數、其他 run 不帶）、`app-server.test.ts`（`thread/start` 的 config：MCP 隔離仍在、加上點號 key）。真實 CLI spike（gpt-6-luna、low）：exec 約 21.6k → 14k input；app-server 一般 run 能跑 shell、promptOnly 的 run 沒有 shell、沒有多出 MCP server。根目錄 `pnpm check` 通過。
- **沒驗證到**：裁判與安全預審的判斷品質（它們本來就不該用工具）；**app-server 的 run 不回報 token 用量**，所以預設 transport 下 Codex 不會出現在「用量分布」，省下多少也看不到。

### 精簡助理大腦（2026-11-25，分支 `lean-assistant-brain`）

- **問題**：Claude CLI 當助理大腦時帶 `user,project` 設定與全部內建工具（實測 28 個工具、81 個 skills），而助理只用得到 `joy_assistant` MCP 工具。spike 時還發現：助理跑在 plan mode（`read-only`），**plan mode 會拒絕沒標 `readOnlyHint` 的 MCP 工具**，`--allowedTools` 也放不過，所以 Claude 大腦的助理其實叫不到自己的工具（預設大腦是 OpenAI API，所以沒人發現）。

### `pnpm joy open` 自動帶入存取權杖（2026-11-25，分支 `joy-open-token`，secret handling 擁有者已審）

- **問題**：打開建好的網頁介面（`pnpm joy start` 或背景服務）時，要自己到 `~/.joy/api-token` 找檔案、複製、貼上。
- **做法**：`pnpm joy open [--port N]`（`packages/server/src/open-joy.ts`）先確認 Joy 有在跑，再讀 `api-token`（沿用 server 的 `readApiToken`：拒絕 symlink、POSIX 要 owner-only），在 `JOY_HOME` 以 `wx`＋`0600` 建一個暫時網頁，內容只有 `location.replace("http://127.0.0.1:<port>/#token=…")`（`no-referrer`，`<` 跳脫），用 `open`／`rundll32 url.dll,FileProtocolHandler`／`xdg-open`（不經 shell）打開，30 秒後刪除；瀏覽器沒打開也會刪。權杖不在指令列，所以同一台電腦的其他使用者從 `ps` 看不到；放在 fragment，所以不會送到 server 或寫進 server log。網頁（`apps/web/src/token-handoff.ts`）在任何 API 請求之前讀 `#token=`、格式對才存進 localStorage，並用 `history.replaceState` 拿掉整個 fragment（格式不對也拿掉），保留原本的路徑與 query。權杖頁的說明多了「在終端機執行 `pnpm joy open`」；背景服務安裝完的提示與 README 改成用 `pnpm joy open`。
- **測試**：server `open-joy.test.ts`（網址、跳脫、三個平台的指令、權杖只在 0600 網頁裡不在指令列、用完刪除、瀏覽器啟動失敗也刪除）；web `token-handoff.test.ts`（只收格式對的、存好後拿掉、不對的也拿掉、其他 fragment 不動）；e2e `access-token.spec.ts`（帶 `#token=` 打開不出現權杖頁、網址沒有 fragment 且保留 query、請求都帶這個權杖、重新整理仍登入）。手動跑 `pnpm joy open --port 4391`（沒有 Joy）顯示啟動提示並回傳 1。根目錄 `pnpm check` 通過（1681 tests）。
- **沒驗證到**：沒有真的打開瀏覽器（本機在跑的 Joy 是舊版網頁）；Windows 的 `rundll32` 與 Linux 的 `xdg-open` 只有單元測試；snap 版瀏覽器可能讀不到 `~/.joy` 裡的暫時網頁。
